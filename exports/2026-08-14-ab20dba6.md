**health가 dream에서 가져가면 좋은 것:**

## 먼저 구조

카테고리는 6개 고정 선택지(채소·과일 / 단백질 / 곡류 / 유제품 / 양념·소스 / 기타)이고, 이름은 자유 입력입니다. AI에게는 이렇게 묶여서 전달됩니다:

```
## 보유 식재료
- 단백질: 소고기
- 채소·과일: 채소
```

즉 **카테고리는 그룹 라벨 역할만** 하고, AI가 실제로 보고 판단하는 건 이름입니다. 카테고리를 잘못 골라도(소고기를 "기타"에 넣어도) 답변 품질에 큰 영향은 없습니다.

## 실측 비교

**"소고기", "채소"로 뭉뚱그린 경우** — 이해는 합니다. 소고기 채소볶음을 정상적으로 제안했습니다. 다만 두 가지가 생깁니다:

- 칼로리 계산을 위해 **AI가 부위를 임의로 가정**합니다 → "소고기(안심 기준) 250g, 약 350kcal". 실제로 갖고 계신 게 차돌박이나 삼겹살 같은 부위면 칼로리가 2배 가까이 차이납니다
- "채소"는 끝까지 **"채소 200g"으로 뭉뚱그려진 채** 나옵니다. 어떤 채소인지 특정하지 않으니 조리법도 "준비한 채소를 넣고"처럼 두루뭉술해집니다

**"소고기 등심", "브로콜리", "파프리카"로 구체적으로 적은 경우** — 확실히 달라집니다:

- 부위 기준이 명확하니 칼로리가 정확해집니다 (등심 200g = 460kcal)
- 재료별로 조리법이 갈라집니다 ("브로콜리는 1~2분 데치고, 파프리카는 채 썰어 육즙에 볶고")

## 정리하면

| | 뭉뚱그린 이름 | 구체적 이름 |
|---|---|---|
| 이해 여부 | 문제없이 이해함 | 이해함 |
| 칼로리 정확도 | AI가 부위를 가정 → 실제와 차이 가능 | 정확 |
| 조리법 구체성 | 두루뭉술 | 재료별로 구분 |
| 식재료 부족 모드 | 판정이 애매해짐 | 명확 |

특히 **식재료 부족 모드(pantry-only)**에서는 "목록에 있는 재료만 쓰라"는 규칙이 걸려 있는데, "채소"라고만 적혀 있으면 AI가 "브로콜리를 써도 되나?"를 스스로 해석해야 합니다. 이번 테스트에서는 관대하게 해석해서 그냥 "채소"로 뭉갰지만, 상황에 따라 판단이 달라질 수 있는 지점입니다.

**권장**: 부위나 종류가 칼로리를 크게 좌우하는 것(소고기 → 등심/안심/차돌박이, 돼지고기 → 목살/삼겹살)은 구체적으로 적으시고, 나머지는 편하게 적으셔도 무방합니다. 카테고리 선택 자체는 크게 고민 안 하셔도 됩니다.

2026-08-19 PR #18로 반영된 두 가지 데이터 품질 결정.

## 신체 지표 — 버림(내림)이 정책, 반올림 아님

`lib/ai/limits.ts`의 `floor1()`로 **소수점 첫째 자리까지 버린다** (70.99 → 70.9,
30.55 → 30.5). 체중계·인바디 표기 정밀도가 0.1 단위라 그 이상은 잡값.
반올림으로 바꾸지 말 것 — 사용자가 명시적으로 버림을 지정했다.

**부동소수 함정**: `21.5 * 10 === 214.99999999999997`이라 단순 `Math.floor`면
21.4로 깎인다. `floor1`은 `(value*10).toFixed(6)`로 보정한다. 이 보정 때문에
FP 잡음값(74.99999999999994)은 75로 올라가는데, 이는 의도된 동작이다.

적용 지점: 신체 지표·온보딩·설정의 저장 경로, 기록 목록 표시, 그리고
`trimContextForPrompt`(정규화 이전에 저장된 긴 소수 기록 정리 + 프롬프트 길이 통제).

## 신체 지표 — 필드 간 물리적 검증

각 필드 독립 검증만으로는 체중 50kg + 골격근량 90kg가 통과했다.
`muscleConsistencyError()`가 두 단계로 차단한다:
- 골격근량 > 체중 → 불가
- 체지방률 입력 시 골격근량 > 제지방량(체중 × (1 − 체지방률/100)) → 불가
  (골격근은 제지방량의 부분집합)

**주의**: 체중 미입력 상태에서는 검증을 건너뛴다. `Number("") === 0`이라
골격근량만 먼저 입력하면 오탐 에러가 뜬다 (Codex 리뷰가 잡은 실제 버그).

## 식재료 카테고리 폐지

6개 카테고리(채소·과일/단백질/…)를 **제거했다**. 판단 근거:
- 프롬프트의 카테고리 그룹핑은 정보를 더하지 않음 — 모델은 "소고기=단백질"을
  이미 알고, 빈 카테고리는 렌더링조차 안 돼서 결핍 신호도 못 줬다
- `getIngredientsByCategory()`와 `byCategory` 인덱스는 **호출부 없는 죽은 코드**였다
- 등록 시 셀렉트를 고르는 입력 마찰만 남아 있었다

DB **v3 마이그레이션**으로 `byCategory` 인덱스 제거. 기존 레코드의 `category`
값은 읽지 않으므로 그대로 둬도 무해. 프롬프트는 평면 목록(`- 닭가슴살`).

되돌리려면 DB 버전을 다시 올려야 하므로, 분류가 필요해지면 프롬프트 레벨에서
모델에게 맡기는 쪽을 먼저 검토할 것.
